 Best Current Practices for Publication of DS Automation Events in RDAP
                 draft-newton-regext-rdap-ds-automation

Abstract

   This document describes the best current practices for the
   publication of RDAP events in domain registrations regarding the
   automated maintenance of Delegation Signer (DS) records as described
   in RFC10026.

1.  Introduction

   [RFC10026] describes best current practices regarding the automated
   maintenance of Delegation Signer (DS) DNSSEC resource records.  This
   document describes the publication of those maintenance events in
   RDAP.

   [RFC9083] defines an RDAP event as a JSON object with three members,
   "eventAction", "eventDate", and "eventActor".

   {
     "eventAction": "this thing happened",
     "eventDate": "2026-08-14T00:00:00Z",
     "eventActor": "I did it"
   }

                        Figure 1: Example RDAP Event

   Both the "dsData" and "keyData" structures of the "secureDNS" object
   in RDAP domain registrations have distinct events.

   "secureDNS" : {
     "delegationSigned" : true,
     "dsData" : [
       {
         "algorithm" : 13,
         "digest" : "B9BEC0EAC0F064929C8586DB185537787015EC3A48F0894BEA74DEEA452F3060",
         "digestType" : 2,
         "events" : [
           {
             "eventAction" : "registration",
             "eventDate" : "2018-03-27T20:09:08Z"
           },
           {
             "eventAction" : "last changed",
             "eventDate" : "2022-04-27T20:19:46Z"
           }
         ],
         "keyTag" : 47828
       }
     ]
   }

                  Figure 2: Example RDAP secureDNS object

   The "eventAction" value of RDAP events are registered in the IANA
   RDAP JSON values registry.

   capitals, as shown here.

3.  The "DNSSEC Automation" Event Actor

   For any event in the "dsData" or "keyData" objects that is a result
   of an action taken by the authority of the DNS system (i.e., a domain
   registry for domains or RIR for reverse-domains, "Registry-Led"), the
   "eventActor" MUST have a value of "DNSSEC Automation".

4.  Event Actions

   Use the following registered event actions:

   *  registration

   *  last changed

   *  deletion

   RFC10026 mentions historical data... let's discuss.

5.  "dsAutomation0" RDAP Profile Extension

   RDAP servers compliant with this document MUST use the
   "dsAutomation0" RDAP profile extension, where profiles are described
   in [I-D.draft-ietf-regext-rdap-extensions].
